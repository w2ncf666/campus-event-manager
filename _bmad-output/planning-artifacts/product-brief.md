# 社团活动报名与候补系统产品简述

2026-11-20 · v0.1 · 三人组会评审稿

首版服务一个社团的限额活动。参与者自行查到报名和候补状态，活动负责人按顺序处理递补。签到岗使用同一份活动名单完成签到和现场补录，财务从中导出记录。

## 要解决的问题

羽毛球社有一场限 16 人的周六活动。负责人用 QQ 群公告和接龙收报名，人工分正式与候补，再把名单抄到在线文档供副社长签到。负责人提到一次递补成功后签到名单未更新，导致到场者被误拒。重复报名和临界名额反复询问也增加了核对工作。

这个案例来自负责人答复的组内转述。评审时补记访谈日期和方式。本次首版范围以该类活动为试用场景。

## 使用者与首版流程

| 使用者 | 需要完成的事 |
| --- | --- |
| 活动负责人 | 发布限额活动，设置容量、时间地点和报名截止。查看队列并手动发起递补，把系统生成的邀请信息通过 QQ 私聊发给受邀者。 |
| 活动参与者 | 报名、退出、自查本人结果和候补位置。收到有效邀请后决定是否接受递补。 |
| 签到岗（示例为副社长） | 查看实时名单，登记签到、释放未到者座位并处理现场补位。 |
| 财务 | 按权限查看对账所需信息，下载与现场记录一致的 Excel 名单。 |

报名满额后进入候补。递补邀约期间为受邀者留位，接受后本人状态与签到名单同步。开场后按现场规则处理座位释放和补录，保留原释放记录和最终出席结果。

## 首版范围与验收目标

首版覆盖活动与报名、候补与递补、签到与现场补录、统计与导出。16 人及访谈中的各个时点用于演示，容量、报名截止和邀请时限按活动设置。公告和发送邀请信息继续通过 QQ，收款继续沿用群 AA。支付、催缴、退款、缴费标记、QQ 自动通知、短信通知、离线同步和学校统一登录在首版范围外。

首版目标是使用同一份名单走完一次模拟活动，并通过以下四个场景。

| 场景 | 通过标准 |
| --- | --- |
| 末位并发报名 | 按系统记录的提交顺序，先提交者取得最后一席，另一人进入候补。同一学号只有一条有效报名。 |
| 候补递补 | 一个空位最多分配给一人。有效邀请确认后，本人状态和现场名单同时反映结果。 |
| 现场放位 | 到释放时点且满足规则后，由签到岗手动操作。一个释放座位只补一次，先处理在场候补。 |
| 签到与导出 | Excel 与现场名单一致。释放后再入场的人只计一次，同时可查释放记录和最终出席。 |

## 定稿条件

组会确认重发时限、本人查询和岗位权限、现场身份关联、名单加载验收、晚到与缺席口径、线上与现场交接。确认后把结论回填到正式简述与 PRD，并核对教师要求的截止日期和提交形式。
