# 社团活动报名与候补系统项目规约

2026-11-24 · M2 评审稿

以 [PRD v0.2](PRD.md) 和 [架构决策](architecture.md) 为开发依据。候补与现场交接使用 [PR #3 的 AC-07](https://github.com/w2ncf666/campus-event-manager/pull/3) 作为补充评审用例。M1、M2 的课堂通过情况待记录。库表迁移和业务实现按课堂评审通过后的冲刺计划推进。

## 技术环境

| 组件 | 统一版本与用途 |
| --- | --- |
| CPython | 3.14.10 |
| Django | 5.2.19 LTS，单体应用，页面采用 Django 模板和少量 JavaScript |
| 数据库 | MySQL Community 8.4.13 LTS，InnoDB |
| 数据库驱动 | mysqlclient 2.2.8 |
| BMAD Method | 6.12.4 |

开发与 CI 使用同一版本组合。组员机器上的安装、MySQL 连接和空库迁移待实测。

## 实现规则

| 编号 | 实现约束 | 评审时核对 |
| --- | --- | --- |
| CTX-01 | 每个读写请求在后端校验活动范围、当前角色和操作对象。参与者读取本人状态依赖有效会话，邀请确认还须核对受邀人、专属链接和正确验证码。换发个人凭证会撤销旧凭证及其会话。工作人员权限绑定活动和岗位。 | FR-03、FR-05、FR-11、ADR-006、AC-05。用甲的会话读乙、跨活动操作或使用已撤销会话时请求被拒绝。 |
| CTX-02 | 学号是保留前导零的字符串。同一活动内按活动 ID 与学号去重，报名、邀请、签到、补录和导出均关联同一个参与者 ID。现场匹配到原记录就复用，姓名与学号冲突时先核验。 | FR-02、FR-09～12、ADR-003。重复报名与现场补录共用一条人员记录。 |
| CTX-03 | 候补邀请负责人牵头公共模型及初始 Django migration，报名负责人复核队列与唯一约束，现场负责人复核名单读写、签到和历史。组内架构评审通过后统一模型和迁移方案，三个模块以同一次公共迁移为起点。 | ADR-003、ADR-004。排查同一业务字段的重复定义，实测 MySQL 空库迁移。 |
| CTX-04 | 分配、接受、退出、释位及补位都走统一的活动事务。MySQL 写入先锁对应活动行，再读当前状态和服务端时钟。一次确认在同一事务中把有效留位转换为原席正式占用。现场补位对同一 Seat 同时写入占用和签到，任一写入失败则整体回滚。 | FR-02～05、FR-08、FR-09、ADR-004、AC-01、AC-05。两个独立 MySQL 连接争最后一席时只有一个获得该席。模拟签到保存失败，席位和签到均保持原状。 |
| CTX-05 | 由当前线上正式占用、现场新增占用和仍有效的邀请留位合计计算活动余量。一人、一席最多各关联一个有效留位，重复请求保持原处理结果和席位状态。确认与退出争用时按服务端处理顺序生效。 | FR-02～05、FR-09、ADR-004、AC-01、AC-02、AC-05。测试请求重放后占用、留位与审计事件数量。 |
| CTX-06 | 服务端按带时区的时间比较，数据库统一按 UTC 写入，页面显示 Asia/Shanghai。停发时点开始拒绝新发及重发。邀请到期取首次发出时间加配置时限与活动最晚确认时点之间的较早值，达到到期时点后按无效处理。 | FR-04～06、ADR-005、AC-02。示例 11:50 发出的原邀请在 13:29:59 可确认，13:30 到期并停止占位。 |
| CTX-07 | 跳过记录绑定席位 ID、空位轮次、候补人和原因，保留候补原序。拒绝、超时或作废后同一空位继续原轮次，席位被正式占用后再次空出才开启新轮次。拒绝和超时退出本场线上递补，现场资格按原序保留。 | FR-04～06、ADR-005、AC-06。空位 1 跳过 A 后，独立空位 2 仍可按序提示 A。 |
| CTX-08 | 重发时沿用原受邀人、席位、轮次、硬到期时点与冷却状态，换发链接与码并使旧凭证失效。连续 5 次错码暂停该邀请确认 5 分钟。保存校验所需的安全摘要，日志及导出排除原始凭证和验证码。 | FR-05、FR-06、FR-11、ADR-006、AC-02。检查旧凭证、冷却状态与原到期时点。 |
| CTX-09 | 签到岗重新读取同一活动正式名单时看到已经提交的邀请确认结果。开场时先使用已经空出的席位，原正式人员未到的席位由签到岗在达到释放时点且满足条件后手动释放。两个模块共同读取席位状态。 | FR-05、FR-07～09、ADR-003～005、AC-03 及补充 AC-07。分别检查 13:30 到期、14:00 使用已有空位和 14:30 手动释位。 |
| CTX-10 | 把原报名类别、入场方式、实际签到、释放、阶段缺席与最终出席留作可区分的记录。有效报名按最后一轮状态汇总，最终出席按实际签到的参与者 ID 去重。Excel 在活动结束后由获授权财务导出，每人一行。 | FR-08～12、ADR-003、AC-04。释放后重新入场者仍导出一行，保留释位和阶段缺席，最终出席与实际签到及汇总一致。 |
| CTX-11 | 用例同时回指 PRD 编号和对应故事。并发证据来自真实 MySQL 的独立连接。移动端性能用同一部署、手机、浏览器和 Wi-Fi 对 100 条模拟报名记录实测 10 次，至少 9 次能在 2.0 秒内读取首屏并操作签到。保持开发状态与实际验证记录同步。 | NFR-01、NFR-02，AC-01 及 PRD 移动端验收。评审核对测试输出、十次计时和部署版本。 |
