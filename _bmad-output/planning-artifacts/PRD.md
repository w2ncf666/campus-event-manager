# 社团活动报名与候补系统 PRD

2026-11-23 · v0.2 · 组内确认修订

首版服务单个社团的限额活动。参与者自查本人状态，组织者从同一份名单处理报名、递补、签到和导出。场景来自羽毛球社负责人答复的组内转述，首版规则以模拟评审为起点，候补跳过规则及分工已在 11 月 23 日得到[组内确认](组会决议与分工.md)。下文是实现与验收基线，测试结果在开发后记录。

支付、催缴、退款、缴费标记、QQ 自动通知、短信通知、离线同步和学校统一登录在首版范围外。公告、私发链接与确认码及群 AA 收款继续通过 QQ。

[产品简述](product-brief.md)

## 1. 角色与身份

| 角色 | 访问和操作 |
| --- | --- |
| 活动负责人 | 登录后管理获授权的活动。核验参与者身份、发放或换发个人凭证，查看活动的完整报名名单，执行候补邀请、跳过与重发。 |
| 参与者 | 使用绑定本场活动与本人记录的专属个人凭证建立会话。可报名、查本人或退出。处理一次邀请时还需同一人的有效邀请链接和正确确认码。 |
| 签到岗 | 登录后进入获授权活动，查看姓名、必要的学号区分信息、报名状态和签到所需留言。现场可输入完整学号作精确核对，可签到、登记在场、登记留言、释放和补录。 |
| 财务 | 登录后只读获授权活动的对账字段、报名和出席汇总，活动结束后下载 Excel。 |

负责人根据线下核验建好姓名和学号，使用 QQ 私聊发送系统生成的不可猜测的个人凭证。演示人员可预置。学号保留前导零，用于匹配和同场去重，身份校验使用个人凭证或工作账号。每个请求都校验活动、权限及操作对象。换发个人凭证时旧凭证和旧会话失效。凭证、确认码与联系方式不进入导出或公开演示数据。

## 2. 活动时点与名额

所有时点按 Asia/Shanghai 显示，以服务端执行校验和分配时的时钟为准。各时点和邀请时限由负责人按活动配置。邀请时限须为正数，报名截止不晚于停发，停发不晚于最晚确认，最晚确认不晚于开场，开场不晚于释放时点，释放时点不晚于缺席判定，缺席判定早于活动结束。

| 项目 | 规则 | 羽毛球场景验收值 |
| --- | --- | --- |
| 报名截止 | 截止时刻起拒绝新报名与新候补申请 | 周四 22:00 |
| 停发 | 停发时刻起拒绝新发与重发，已发且尚有效的邀请可继续处理 | 周六 12:00 |
| 邀请到期 | 取首次发出时间加邀请时限与最晚确认时间中较早的时点。到期时刻起不可接受或拒绝，留位不再占名额 | 单次 2 小时，最晚 13:30。11:50 发出的邀请在 13:30 到期 |
| 开场 | 到开场时刻起关闭自行退出，签到岗可签到并用自然空位现场补位 | 14:00 |
| 释放 | 到释放时刻起可人工释放尚未签到且没有有效保护的线上正式座位 | 14:30 |
| 缺席判定 | 按该时点前的记录判定阶段缺席，晚到留言的座位保护同时到期 | 15:00 |
| 活动结束 | 到结束时刻停止签到、释放和补录，按记录生成最终结果 | 16:00（补充测试值） |

演示容量为 16。仍占座的线上正式名单、有效邀请留位与现场新增席位合计不超过容量。一次邀请接受只把原留位转换成正式席位，正式报名者签到沿用已有席位。同一请求重试不重复生效，争用同一空位只能分配一次。确认与退出按系统记录的处理顺序执行。先退出则原邀请失效，先确认仍可在开场前退出并归还席位。

## 3. 功能需求

### 活动与报名

| 编号 | 需求 |
| --- | --- |
| FR-01 | 负责人配置容量、时间地点及各阶段时点并发布活动。参与者可查看本场活动信息。 |
| FR-02 | 每场同一学号沿用同一个参与者 ID，最多有一条当前有效报名。系统给成功提交分配唯一序号，按服务端序号分配名额。没有尚待邀请的线上候补且有未被留位占用的空席时，可直接正式报名。正式占用和有效邀请留位合计达到容量，或已有尚待邀请的线上候补时，新报名排在队尾。 |
| FR-03 | 参与者查询本人的正式、候补、待确认、可现场候补、已退出或座位已释放等状态。线上候补可查随队列更新的位置。开场前可退出，退出同时移出候补、撤销未处理邀请或释放本人占用的线上席位。截止前重新报名复用参与者 ID，生成新报名轮次和序号。旧轮次保留，上一轮的邀请凭证不能用于新轮次。主动退出者到场时走临时流程。 |

### 候补与邀请

| 编号 | 需求 |
| --- | --- |
| FR-04 | 有空位时按线上候补的原序号提示当前空位可受邀的下一人，略过该空位本轮已跳过的候补。负责人点击后为该人保留一席，生成专属链接和 6 位确认码，由负责人分别私发。一个候补同时最多有一个留位，多席自然空位可按序分别邀请。 |
| FR-05 | 受邀者本人持有效链接和正确码接受或拒绝。接受同步更新本人状态与签到名单。拒绝或到期解除留位并退出本场线上递补，由负责人发下一条。连续 5 次错码后同一邀请暂停确认 5 分钟，仍按原时点到期，重发沿用该暂停状态。 |
| FR-06 | 负责人填写理由，可在当前空位的这一轮递补中跳过一位候补。系统保留其原候补序号和其他空位的线上递补资格。若此人已为该空位留位，则作废该邀请并解除留位，该空位继续当前轮次。处理这个空位时系统继续提示其他候补。出现另一个独立空位，或一个已经重新分配的席位再次空出时，仍符合条件且没有有效邀请的人可按原序号受邀。负责人也可在停发前且原邀请有效时作废重发，重发沿用原受邀人、候补序号、席位和到期时刻，同时换发链接与码。拒绝、超时者退出本场线上递补。拒绝、超时和跳过者到场后可按原候补序号进入现场候补。主动退出者走 FR-03。 |

### 签到、现场补位与导出

| 编号 | 需求 |
| --- | --- |
| FR-07 | 签到岗使用来自同一活动记录的名单，重新读取时可看到最新有效报名与确认结果。开场后手动勾选已获正式席位且到场的人。 |
| FR-08 | 签到岗核对 QQ 晚到留言，可在缺席判定时点前为尚未释放的正式席位登记确认时间和理由，保护到判定时点。释放时点起由签到岗人工释放未签到且无有效保护的正式席位。到达缺席判定时点时，以该时点前的记录为准，为未签到且无已确认留言的线上正式参与者记一次阶段缺席，已退出者除外，已经释放者仍可记阶段缺席。系统可在判定后的首次读取补记。 |
| FR-09 | 到开场时刻，所有线上留位均已转换、解除或到期。开场起已有空位及其后释放的空位统一补位。签到岗按本场活动和核验过的学号复用原记录，首次到场且无原记录才新建现场记录。姓名与学号冲突时先核验再操作。核对仍在场后，先按原序号接纳现场候补，再按现场登记顺序接纳临时人员。原正式席位已释放者走临时流程。现场补位成功时同时登记签到。 |
| FR-10 | 自活动结束时刻起，财务可导出 Excel。每个活动按学号一人一行，包含姓名、学号、原报名类别、最终入场方式、签到时间、释放时间与理由、阶段缺席及最终出席。晚到者合法重新入场时，保留释放和阶段缺席的历史。 |
| FR-11 | 报名、本人查询、邀请、签到、释放、补录和导出按活动及角色授权。保留状态变化的时间、操作人或系统来源，跳过、重发、释位等记录理由。 |
| FR-12 | 按每人最新一轮报名的状态统计有效报名数。正式和候补报名计入，主动退出者不计入。席位释放仍保留该轮报名。最终出席数按实际签到者去重。曾获线上正式席位且未退出、结束时仍未签到者记最终缺席。只候补而未获席、主动退出且未现场入场及临时到场未获席的人员不计缺席。 |

原报名类别保留为正式、候补或未报名。最终入场方式记录为线上正式、现场候补、现场临时或未入场。阶段缺席、释放和最终出席各自记录。同一个人匹配到已有记录时，补录复用记录，保留历史。

## 4. 功能验收

使用模拟人员与活动数据，各子用例从独立的初始状态开始。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| AC-01 最后一席 | 活动已有 15 人正式，两个不同学号并发报名，再重放其中一个请求。另测报名截止前后、截止瞬间、已有候补时空出名额、15 席正式加 1 席有效留位，以及取消后再报。 | 服务端先序号者得到第 16 席，另一人进候补。同学号只有一条有效记录。截止瞬间与之后拒绝新申请，已有在先候补或正式占用加有效留位达到容量时新报排队。重报沿用参与者 ID 并获得新序号，旧轮次可追溯且其邀请失效。 |
| AC-02 邀请边界 | 11:50 发出并留位，测试停发前重发、12:00 尝试重发。另用有空位和合格候补的活动在 12:00 尝试新发。以正确凭证在 13:29:59、13:30 处理独立邀请，并测试错码、拒绝、重试。 | 重发后旧凭证失败，席位和 13:30 的期限不变。12:00 新发与重发均失败。到期前本人可接受或拒绝，到期瞬间不可处理且释放留位。正确接受只转换一次留位并更新本人及现场名单。错码不会确认，连续 5 次失败触发冷却。 |
| AC-03 释放与现场候补 | 14:00 使用已有空位补位。另测 14:29:59 和 14:30 对未签到且无留言保护的正式席位执行释放。两名在场候补按原序号相反的顺序到场，另有临时人员。对有确认留言的未签到人员在 15:00 前后尝试释放。 | 14:00 可用已有空位，14:29:59 不可释放正式席位，14:30 起符合条件的座位可人工释放。补位先给原序较靠前的在场候补，同一席只补一次。已确认留言的保护到 15:00，届时可手动释放。15:00 无已确认留言且仍未签到的正式人员记阶段缺席。 |
| AC-04 补录、签到和导出 | 原线上正式人员因未到已被释放并记阶段缺席，15:00 后到场。候补已处理完且有空位，经签到岗核验后按临时流程补录。另一名带留言的正式人员始终未到。16:00 财务导出。 | 释放后再入场者保留原类别、释放和阶段缺席历史，最终类别为现场临时、最终为出席，Excel 只一行。带留言但始终未到者记最终缺席。汇总人数与 Excel 一致，16:00 起不再录入。 |
| AC-05 权限、重试与交接 | 只用学号查询，尝试用甲的会话读乙的记录或确认乙的邀请。另测跨活动读取、签到岗导出、财务改签到、换发后使用旧个人凭证及会话。模拟退出与确认争用、重发或补位重试、拒绝或跳过人员现场到场。 | 越权操作被拒，旧个人凭证与会话失效。先退出时确认失败，先确认时随后退出归还一席。重试不重复占位或释放。开场时线上无有效留位，拒绝或被跳过者现场仍按原序号参与。 |
| AC-06 按空位跳过 | A 为候补队首，处理空位 1 时给出理由跳过 A，随后为后位候补发出邀请。用同一空位测试重试与超时。然后在停发前由另一位正式报名者退出形成空位 2。另测 A 已持有其他有效邀请时处理空位 2。 | 空位 1 保留跳过记录和理由，重试或超时后继续提示其他候补，A 的原序号保留。空位 2 优先提示仍符合条件且没有有效邀请的 A。A 已有有效邀请时不重复留位，跳过空位 1 不影响其他空位的邀请。 |

## 5. 移动端验收

使用同一部署版本、同一部手机、浏览器和 Wi-Fi。准备本场 100 条模拟报名记录，包含正式、候补和历史记录。先打开名单一次预热，再每次从活动入口打开名单并记录耗时。计时从点开名单开始，到首屏能读取且签到控件可操作为止。连续测 10 次，至少 9 次不超过 2.0 秒，加载失败计为超标。验收记录保留设备、浏览器、网络、部署版本与 10 次测量值。
