# 社团活动报名与候补系统 PRD

**v0.1 · 组内评审草案 · 2026-11-20**

## 1. 目标与首版范围

参与者自行查询报名状态，组织者用同一份活动名单完成报名、递补、签到和导出。羽毛球社负责人提到，曾有候补者收到私聊补位通知，因签到名单未更新而在到场后被误拒。[产品简述](product-brief.md)

首版面向一个社团的限额活动。以下功能和验收项以 2026-11-20 的访谈评审稿为基线，经组会确认后定稿。标记 D1–D6 的规则或验收条件待定。支付、催缴、退款、缴费标记、QQ 自动通知、短信通知、离线同步和学校统一登录在首版范围外。负责人继续通过 QQ 发公告、私聊转发邀请，收款沿用群 AA。

## 2. 角色与名单

| 角色 | 可见信息与操作 |
| --- | --- |
| 参与者 | 查看活动信息、本人状态及候补位置。凭有效链接和正确的本次确认码处理本人邀请。 |
| 活动负责人 | 发布活动、查看活动人员、处理候补邀请。联系方式按联络需要开放。 |
| 副社长 | 查看签到所需字段，手动登记签到、释放名额和现场补录。 |
| 财务 | 查看对账所需字段和出席结果，下载活动 Excel 名单。 |

同一场活动的报名、邀请、现场和导出用同一份名单记录。报名阶段的身份、实际出席结果和释放历史分别记录。名额被邀请暂留时仍算占用，候补确认后把该留位转成正式名额。现场补录与既有报名、导出类别的对应见 D3。

## 3. 功能需求

| 编号 | 功能 | 预期行为 |
| --- | --- | --- |
| FR-01 | 发布和配置活动 | 负责人设置时间地点、容量和报名截止并发布活动。活动页显示参与者报名所需信息。邀请时限按活动设置，停发邀请和现场各阶段的时点遵循本场活动规则。 |
| FR-02 | 报名分配和去重 | 系统按记录的提交顺序分配名额，满额时加入候补。并发提交时结果仍有唯一顺序，每场活动同一学号最多一条有效报名。截止后拒绝新的报名和候补申请。截止前取消后再报按新提交顺序排列。存在候补时遇到空位的优先级待 D6。 |
| FR-03 | 状态自查和退出 | 参与者可查看本人正式、候补或待确认状态，候补位置随队列变化更新。已有参与者在报名截止后仍可退出，最晚退出时点和涉及有效邀请时的处理见 D6。本人查询的校验方式见 D2。 |
| FR-04 | 发出邀请并留位 | 有可用名额时，系统指出符合规则的下一位候补。负责人点击邀请才生成专属链接及本次 4–6 位确认码，开始计时并留出一个名额。负责人通过 QQ 私聊转发。用发出时间加上配置时限，再和活动最晚确认时点比较，以较早的时点为到期时刻。停止新发邀请后，之前生成的有效邀请仍可处理。候补资格和跨阶段留位见 D6。 |
| FR-05 | 确认、拒绝和超时 | 有效链接及正确确认码均通过校验后，受邀者可接受或拒绝。接受时同一笔留位转为正式，参与者状态和签到名单均反映新结果。拒绝或超时后结束本次留位，后续由负责人决定何时发下一条。每条邀请的处理结果只生效一次。系统拒绝错码和过期请求，重复提交保持已产生的结果。 |
| FR-06 | 跳过与作废重发 | 负责人可以记录理由后跳过某人当轮资格，或作废一条邀请再重发。系统保留原候补顺序、操作者、时间和处理结果。作废后旧链接和旧确认码失效，重发权限、是否沿用原到期时刻和时间等号见 D1。 |
| FR-07 | 实时签到名单 | 副社长打开活动名单，查看已确认的正式人员及签到所需信息，手动登记签到。报名与递补更新后，重新读取名单时应看到相同状态。移动端可用时间按 D4 验收。 |
| FR-08 | 人工释放与缺席记录 | 到释放时点提醒副社长检查迟到者。可为有留言者保留座位并记录理由。符合条件的未到者由副社长手动释放，保留释放时间和人员记录。按缺席时点及留言条件登记缺席。留言效力、执行方式和之后到场的处理见 D5。 |
| FR-09 | 现场补录和名额优先顺序 | 副社长将释放的空位先分给在场候补，按原候补序号排序。候补处理完后，按到场先后接纳临时到场者。已释放的正式报名者后来到场，按临时到场流程处理。每个空位只补一次，同一人只计一次实际到场，匹配既有记录的方式待 D3。 |
| FR-10 | 财务导出 | 财务按权限在活动结束后下载 Excel，其中包含姓名、学号、正式／候补／临时到场分类，以及签到、释放、缺席记录。出席结果与现场一致，已释放后又到场的人员仍保留原释放记录。类别映射、冲突处理和导出呈现见 D3。 |
| FR-11 | 岗位授权和最小可见 | 系统按活动和岗位校验本人查询、邀请、签到、释放及导出访问。参与者仅能看本人信息。联系方式、邀请链接及确认码只在相应操作和授权范围使用。岗位分配和具体字段清单见 D2。 |
| FR-12 | 报名与出席统计 | 岗位授权范围内可查看报名和实际出席人数。出席人数按人去重，与现场记录和导出一致。分类计数规则见 D3。 |

仍占座的正式报名、有效邀请留位和现场入场共用活动容量。留位转为正式时只计一个占用，已录为正式的参与者签到时也只占一席。在并发操作下，同一个空位最多被分给一人。现场补录遇到仍有效的邀请留位时，按 D6 确认交接流程。

## 4. 验收场景

下列验收使用模拟数据。示例活动容量为 16，周四 22:00 截止报名。周六 12:00 停止新发邀请，单次最长 2 小时且最晚到 13:30。14:00 开场，14:30 起可手动释放符合条件的座位，15:00 判定未到且无留言者为缺席。分别检查这些时点前后的行为，截止瞬间的处理由组会确认。

| 编号 | 准备与操作 | 预期结果 | 对应需求 |
| --- | --- | --- | --- |
| AC-01 最后一个名额 | 提前填入 15 名正式报名者。两个不同学号在截止前并发报名，同时重放其中一个学号的提交。 | 以系统记录的顺序为准，较早的一人正式报名成功，另一人进入候补。正式名额仍为 16，重复学号仅有一条有效报名。 | FR-01～03 |
| AC-02 邀请跨停发时间 | 在有空位和符合条件的候补时测试 12:01 新发。另设 11:50 已发并留位的邀请，每次从待确认状态起步，分别测试 13:29 用正确链接与码接受或拒绝、13:29 错码、13:31 接受。 | 12:01 新发被拒。旧邀请于 13:30 到期，13:29 正确接受会更新本人状态和签到名单。错码或超时无法确认。有效拒绝或超时解除留位，下一次邀请由负责人发起。重复提交只保留一次有效处理结果。 | FR-04～07、FR-11 |
| AC-03 释放与在场候补 | 14:10 有两名正式报名者未到，其中一人有有效留言。14:31 由副社长释放无有效留言者的座位。此时有两位在场候补，候补序号较靠前的人到场较晚，另有一位临时到场者。推进至 15:00 的缺席判定。 | 14:10 两个座位都保留。到释放时点后，副社长手动释放符合条件的座位，有有效留言者的座位可继续保留。空位先给在场候补中原序号最靠前者，重复点击释放或补位只分出这一席。未到且无留言者记缺席，释放记录仍可查。 | FR-07～09、FR-11 |
| AC-04 同一份名单与导出 | 一名正式报名者被释放，后来在现场符合临时到场规则且确有空位时获准进入。副社长通过活动名单补录和签到，活动结束后财务导出。 | 名单显示补录和签到，仍保留原释放记录。现场统计和 Excel 均把同一人记为一次出席。根据 D3 确认的规则校对类别字段。 | FR-07～12 |
| AC-05 权限与边界补测 | 测试满员时截止前取消再报、截止后新申请、作废邀请后使用旧凭据，以及两次并发占同一空位。尝试以参与者身份查看他人状态、以签到岗导出、以财务身份修改签到。 | 取消再报按新顺序排队，截止后新申请被拒。作废凭据失效，只有一笔操作能占用同一空位。越权读取和修改都被拒绝。具体截止瞬间及岗位权限按组会决议补测。 | FR-02～06、FR-08～11 |

## 5. 首版验收度量

| 指标 | 测试与通过条件 |
| --- | --- |
| 名额与报名一致性 | 执行 AC-01、AC-02、AC-03，超容量、一个名额多人占用、重复有效报名均为 0 次。 |
| 状态与现场一致性 | 执行 AC-02、AC-04，确认后本人状态、签到名单和最终导出均能与同一人及对应记录对上，结果差异为 0 条。 |
| 移动端名单可用时间（D4 待确认） | 提案为加载含 100 条合成报名的同一场活动，记录一部约定测试手机和同一 Wi-Fi，每次返回活动入口后重新打开名单，测 10 次。计时从打开名单到名单可查看和执行签到为止，提议至少 9 次 ≤ 2 秒。组会确认设备、网络、入口状态、数据规模与阈值后写入正式验收。 |

## 6. 待决事项

| 编号 | 组会需要给出的规则 |
| --- | --- |
| D1 重发时限 | 确认何时允许作废重发，以及重发是否沿用原到期时刻。提案是在停发时点起停止重发，重发沿用原到期时刻并作废旧凭据。确认停发和到期瞬间的处理。 |
| D2 本人查询与岗位权限 | 本人身份如何证明，工作人员如何获得岗位权限。明确各岗位查看字段和导出权限，确认链接和确认码的校验、重复试错处理。 |
| D3 现场关联与到场去重 | 如何关联同一人的既有报名，无法匹配时如何处置。确认导出类别、出席统计和释放历史如何呈现。 |
| D4 移动端性能验收 | 确认测试手机、网络、数据规模、开始和结束条件，以及通过阈值。 |
| D5 迟到留言与缺席边界 | 谁记录或确认留言、何时有效、保留到几点。确定缺席判定方式、恰好到达时点以及判定后到场如何记最终出席。 |
| D6 报名空位与候补交接 | 报名截止前已有候补且出现空位时的优先级。确认拒绝、超时或当轮跳过后的候补资格、已有报名最晚退出时点、线上留位如何结清，以及先前未占用的空位何时可用于现场补位。 |

小组补记访谈日期和方式，并向老师核对提交日期和形式。按[组会决议与分工](组会决议与分工.md)确认上述规则，复走四个场景，再把结论写入正式 PRD。
